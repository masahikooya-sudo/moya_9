# 社員への展開手順（本番デプロイ）

テストデプロイで動作確認したアドオンを、社内の社員に一括で配布する手順です。
作業は **Google Cloud コンソール**・**Apps Script**・**Google 管理コンソール** の 3 か所で行います。

| # | 作業 | 場所 | 担当 |
|---|------|------|------|
| 1 | Google Cloud プロジェクトの準備 | Google Cloud コンソール | 開発担当 |
| 2 | Apps Script をそのプロジェクトに紐づける | Apps Script | 開発担当 |
| 3 | 本番デプロイ（バージョン）を作成 | Apps Script | 開発担当 |
| 4 | Marketplace SDK でアプリを「社内限定」で登録・公開 | Google Cloud コンソール | 開発担当 |
| 5 | 対象者へ一括インストール | 管理コンソール | Workspace 管理者 |
| 6 | 動作確認・テスト版の削除・社員へ案内 | Gmail | 開発担当 |

---

## 1. Google Cloud プロジェクトの準備

Apps Script が自動で作る「デフォルトのプロジェクト」では Marketplace に公開できないため、標準の Cloud プロジェクトを用意します。

1. [Google Cloud コンソール](https://console.cloud.google.com/) で、**自社の組織配下に**新しいプロジェクトを作成（例：`scheduling-assistant`）
2. 「API とサービス」→「ライブラリ」で次の 4 つを有効化
   - Gmail API
   - Google Calendar API
   - People API
   - Google Workspace Marketplace SDK
3. 「API とサービス」→「OAuth 同意画面」を設定
   - ユーザーの種類：**内部（Internal）** ← 社外の人は使えず、Google の審査も不要になります
   - アプリ名：日程調整アシスタント／サポートメール：担当者のアドレス
   - スコープ：`src/appsscript.json` の `oauthScopes` にある 9 個をすべて追加
4. ダッシュボードで **プロジェクト番号**（数字）を控える

## 2. Apps Script をプロジェクトに紐づける

1. Apps Script エディタ →「プロジェクトの設定」（歯車）
2. 「Google Cloud Platform（GCP）プロジェクト」→「プロジェクトを変更」→ 1 で控えたプロジェクト番号を入力
3. 次回実行時に再承認が求められます（正常です）

## 3. 本番デプロイを作成

1. 最新のコードが反映されていることを確認（clasp の場合は `clasp push`）
2. 「デプロイ」→「新しいデプロイ」→ 種類「アドオン」
3. 説明に「v1 初回公開」などと入力して「デプロイ」
4. 表示された **デプロイ ID**（`AKfycb...`）を控える

## 4. Marketplace SDK で社内限定アプリとして登録

Google Cloud コンソール →「API とサービス」→「Google Workspace Marketplace SDK」を開きます。

### アプリの構成（App Configuration）

| 項目 | 設定値 |
|------|--------|
| アプリの公開設定 | **非公開（Private）**　※ 後から変更できません |
| インストール設定 | 「管理者によるインストールのみ」または「個別 + 管理者インストール」 |
| アプリの統合 | **Google Workspace アドオン** → 「デプロイ ID」に 3 で控えた ID |
| OAuth スコープ | `src/appsscript.json` の `oauthScopes` と同じ 9 個を入力 |
| デベロッパー情報 | 担当部署名・メールアドレス |

### ストアの掲載情報（Store Listing）

`docs/marketplace/` に素材を用意してあります。

| 項目 | 素材・入力例 |
|------|------|
| アプリ名 | 日程調整アシスタント |
| 簡単な説明 | Gmail から社内外の打ち合わせ日程を調整。空き確認・仮押さえ・メール下書きを自動化 |
| 詳しい説明 | README の「できること」を転記 |
| アイコン（128×128 / 32×32） | `icon-128.png` / `icon-32.png` |
| カードバナー（220×140） | `card-banner-220x140.png` |
| スクリーンショット（1280×800） | `screenshot-1-flow.png` / `screenshot-2-features.png`（実際の画面のスクリーンショットに差し替えるとより親切です） |
| カテゴリ | 仕事効率化（Productivity） |
| 利用規約・プライバシーポリシー・サポートの URL | 社内ポータルや Google サイトのページ（マニュアルや問い合わせ先を載せたページで可） |

入力が終わったら「公開」を押します。非公開アプリは Google の審査なしで、数分〜数時間で社内から見えるようになります。

## 5. 対象者へ一括インストール（Workspace 管理者）

1. [管理コンソール](https://admin.google.com/) →「アプリ」→「Google Workspace Marketplace アプリ」→「アプリリスト」
2. 「アプリをインストール」→「社内アプリ（Internal apps）」から **日程調整アシスタント** を選択
3. 「管理者インストール」→ インストール対象を選択
   - パイロット段階：**特定のグループ**（例：調達部門の数名のグループ）
   - 全社展開時：**組織部門（OU）** 単位で追加
4. 要求される権限（データアクセス）を確認して「同意」
   - 管理者が同意するため、社員一人ひとりの承認作業は不要になります

> **API アクセス制御を使っている組織の場合**：「セキュリティ」→「アクセスとデータ管理」→「API の制御」→「アプリのアクセス制御」で、このアプリを **信頼できる（Trusted）** に設定してください。設定しないとブロックされることがあります。

> **カレンダーの共有設定**：「アプリ」→「Google Workspace」→「カレンダー」→「共有設定」で、社内向けに「空き時間情報のみ」以上を共有できるようになっているか確認してください（空き確認に必要です）。

## 6. 動作確認と社員への案内

1. インストールが反映されるまで **最大 24 時間**かかることがあります。対象者は Gmail を再読み込みします
2. 開発担当は、**テストデプロイを削除**して重複表示を防ぎます
   - Apps Script →「デプロイ」→「デプロイをテスト」→「アンインストール」
3. 対象のアカウントで、メールを開いて右側のパネルにアイコンが出ることを確認します
4. 説明会資料 `docs/日程調整アシスタント_利用マニュアル.pptx` で案内し、各自に「設定」（自社名・氏名・署名・社内メンバー）をしてもらいます

## 更新するとき（バージョンアップ）

デプロイ ID を変えずに新しいバージョンへ切り替えれば、社員側の作業は不要です。

1. コードを修正して反映（`clasp push`）
2. Apps Script →「デプロイ」→「デプロイを管理」→ 本番デプロイの鉛筆アイコン
3. 「バージョン」で **新バージョン** を選び、説明を書いて「デプロイ」
4. **スコープを追加した場合のみ**：Marketplace SDK の OAuth スコープも更新し、管理者が管理コンソールで権限を再承認します

> 「新しいデプロイ」を作るとデプロイ ID が変わり、Marketplace SDK の設定もやり直しになります。更新は必ず「デプロイを管理」から行ってください。
